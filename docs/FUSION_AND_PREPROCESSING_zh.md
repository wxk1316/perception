# 五类、5m、预处理和两帧融合评估

日期：2026-11-07；版本0.2.0。

## 1. 最终改造

模型直接支持 CAR、TRUCK、BUS、BICYCLE、PEDESTRIAN 全部5类，分别输出 car、truck、bus、bicycle、pedestrian。原版前三类合并为 vehicle，本版仅在 /rda/obstacles 兼容规划时做该映射。原始模型类别以模型文件的class_names及真实五通道检测头为依据。配置中的TRAILER/MOTORBIKE是标签重映射目标，不是可凭空增加的预训练类别。[公开模型来源](https://huggingface.co/AutowareFoundation/lidar_centerpoint)。

默认模型点云与几何点云为5m周向范围，最终检测、模型检测、追踪、规划均按当前位姿到包围框最近位置筛选；大车中心在5m外但车头在范围内时保留。模型head解码也按旋转框最近距离筛选，避免提前按中心丢掉大车。坐标中的5m参考点是车体几何中心/当前body的平面参考点。

## 2. 是否要预处理

| 处理 | 几何占据 | 预训练模型 | 理由与代价 |
|---|---|---|---|
| XYZ有限值、字段和时间校验 | 必须 | 必须 | 排除损坏输入；不把坏帧当空地 |
| 有可信时间时单扫描去畸变 | 推荐 | 推荐 | 转弯与自车运动减轻形变；无真实点时间仍报告退化 |
| 车体剔除与5m裁剪 | 启用 | 启用 | 减少自车/远场点和CPU柱化工作 |
| 局部稳健地面分割 | 默认启用 | 默认不删除地面 | 几何不分地面会把道路连成障碍；模型需要保留其训练输入上下文 |
| 模型pillar/采样 | 不代替几何地面 | 必须 | 直接使用权重所需9维柱特征、每柱最多32采样点 |
| 强统计滤波/大体素下采样 | 当前不新增 | 当前不新增 | 32线低安装雷达的小行人/低路沿可能只有少量点，强滤波可增加漏检 |

模型和几何分支共享有限值、外参、自车剔除，但不强制共享去地面结果。模型内地面和历史点有用，不应把非地面二维几何点直接交给该三维预训练网络。几何地面阈值2.5cm、高度和坡度需按实车标定核对；不确定地面保留占据。

## 3. 两帧如何匹配

设前帧点为 p_prev，存储原始源时间 t_prev 与 T_world_prev；当前源时间t_cur和位姿T_world_cur来自同域 /localization 插值。计算：

```text
p_cur = inverse(T_world_cur) @ T_world_prev @ p_prev
time_lag = t_cur - t_prev
```

先处理当前扫描可用的逐点去畸变，再做帧间SE(3)对齐。缓存保存的是上一份未融合原始源云，推理忙而跳帧时也更新缓存；始终是最新两份源云，而不是上两次推理输入。默认最大间隔0.15s；10Hz丢掉一帧后若间隔0.2s，则退为单帧。关闭开关时模型所有点time_lag为0；模型内部不再另叠一帧。

旧帧先转到当前body，再做当前半径与车体剔除。合法空当前帧不会只用旧点生成新输入。动态切换开关会清空跨条件历史、重建模型轨迹并拒绝旧条件在途推理结果；状态给出融合代际及实际模型输入点数。

## 4. 预期作用和局限

两帧可增加短时稀疏人体、自行车和局部遮挡的观测点，T特征让模型区分新旧点。两帧不是翻倍独立信息：道路/静态表面多为重复点，同一个BEV柱可能只增加采样点，未必增加占据柱数。相关观测不保证精度提高。

仅自车对齐不会消除目标自身运动。10Hz下，0.6m/s行人相邻帧可移动6cm，1.0m/s车/自行车可移动10cm。把这些旧点当当前几何会加厚、拖影，甚至连接相邻行人。因此推荐模型可开关两帧，几何始终使用当前源点。它不是“所有分支无条件拼接两帧”；此选择保留几何当前占据和追踪量测时间的含义。更长融合窗口和动态目标分组需要额外运动补偿；多帧按目标运动选择聚合的研究也指出此取舍。[VADet研究](https://arxiv.org/abs/2411.13186)。

5m能减少点处理、聚类和柱化开销，但固定TensorRT模型的BEV/head仍为480×480网格，并不会随点半径自动缩小。因此不能按面积比估算GPU加速倍数。5m输入还会截断边界的大车或减少模型上下文；若边界识别不足，可只将model_input_range设8m或12m，max_obstacle_range仍保持5m，这不会扩大规划输出范围。

## 5. 已执行的合成配对探针

在本机macOS ARM64、ONNX Runtime CPU上执行三组相同源序列。模拟自车每0.1s平移4cm并转动，目标每帧移动6cm，交替稀疏点。以下统计使用最后一帧点数/柱数及5个暖启动后的模型调用中位数，直接调用缓存和网络，不等于完整ROS/车辆并行运行：

| 条件 | 当前+历史点数 | 占据柱数 | 融合/转换准备中位数 | CPU网络推理中位数 |
|---|---:|---:|---:|---:|
| 12m / 单帧 | 8154 + 0 | 3206 | 0.274ms | 553.5ms |
| 5m / 单帧 | 2168 + 0 | 796 | 0.167ms | 533.3ms |
| 5m / 两帧 | 2168 + 2168 | 796 | 0.386ms | 531.9ms |

5m相对12m该合成输入点数减少约73%；两帧增加点数但占据柱数基本不变，CPU网络时延也没有按点数显著缩短。该场景的当前5m几何地面输入2168点，移除1918个地面点，保留250个非地面点。

5m单帧在5个统计源中有2帧输出至少一个框，两帧有4帧，12m单帧有5帧。它只是合成表面上“模型输出出现次数”，没有真实标注、匹配IoU或类别召回统计，不能解读成校园检出率或精度提高百分比；它也提示上下文裁剪可能影响模型输出。这里只能证明接口、密度、边界和几何分支效果可复现。

结果文件verification/fusion_ab_cpu.json；脚本tools/evaluate_fusion.py。真实校园精度、遮挡收益、ID切换和Orin10Hz仍未测量。

## 6. 实车A/B方案

对同一段rosbag分别重启节点回放，固定阈值、外参、range、模型目录及use_sim_time。A仅当前帧，B当前+上一帧：

```bash
ros2 launch campus_perception campus_perception.launch.py config:="$CONFIG_FILE" two_frame_fusion:=false use_sim_time:=true with_rviz:=true
ros2 launch campus_perception campus_perception.launch.py config:="$CONFIG_FILE" two_frame_fusion:=true use_sim_time:=true with_rviz:=true
```

两次分开执行，不同时启动。两组都排除模型初始化和至少1.5s的轨迹确认阶段。重点包括两人交叉、侧后方自行车、停放车、短遮挡、低路沿和转弯。看实际model输入input_fusion_enabled/history_points，而不是仅看期望开关；没有ready模型时只能比较几何/缓存，不能评价模型融合收益。

记录每类有标注的漏检/误检、ID切换、源到输出p95/p99年龄、模型跳帧和CPU/GPU负载。几何去地面消融另用配置ground_enabled=false重启对比；关闭时保留道路点，所以可能出现大路面占据。避免同时更改多个变量。

推荐初始配置为全部5类、5m输出、model_input_range=5m、two_frame_fusion_enabled=true、几何去地面开启；若真实对比显示拖影或误检增加，则关闭融合。保留开关和原始结果供选择，不用合成结果替代实车结论。
